## ข้อเท็จจริงของ V1 ที่ต้องใช้เป็นฐาน (Final V1 Facts)

- **ตัวสินค้า:** ระบบเผยแพร่ข้อมูลอาจารย์ แบบอ่านอย่างเดียว ไม่ต้อง Login
- **แหล่งข้อมูล (Source):** เว็บไซต์สาธารณะของสาขาวิชา ไม่ใช่ไฟล์ Excel/CSV กลาง
- **Controlled Snapshot:** `data/v1/source/faculty_profiles.json`, `data/v1/source/source-metadata.json`
- **สคริปต์เตรียมข้อมูล:** `scripts/prepare_faculty_data.py`
- **โครงสร้างบน S3:** `source/current/`, `serving/`, `metadata/`
- **ข้อมูลที่ให้บริการจริง:** `serving/faculties.json`, `serving/faculties/{id}.json`
- **AWS:** ภูมิภาค `ap-southeast-1`, S3 แบบ private, Lambda, API Gateway, IAM แบบ least privilege
- **Frontend:** Next.js บน Vercel เส้นทาง `/faculties` และ `/faculties/{id}`

**สถานะ:** ✅ ตรงกับที่ implement จริง — ตรวจสอบแล้วจาก `data/v1/source/`, `scripts/prepare_faculty_data.py`, และโค้ด `function_faculties/` ในโค้ดปัจจุบัน

## ข้อมูลจริงที่อัปเดตไว้แล้วใน repo (`data/v1/` และ `build/v1/`)

ระหว่างทำงานนี้ ได้แทนที่ชุดข้อมูลตัวอย่าง 2 คนเดิมด้วย **ชุดข้อมูลจริงจาก S3 จำนวน 22 คน**
(ไฟล์ที่ผู้ใช้ส่งมาจากเครื่อง) และรันสคริปต์เตรียมข้อมูลใหม่ในเครื่องเพื่อพิสูจน์ว่าทำซ้ำได้จริง
ผลลัพธ์ตรงกับที่มาให้ทุกไบต์ (ต่างกันแค่เวลาที่ประมวลผล) ผลสรุป:

```text
จำนวนอาจารย์: 22 คน
ผ่านการตรวจสอบ: 22 คน
ไม่ผ่าน: 0 คน
ผลงานตีพิมพ์ที่เลือก: 7 รายการ
คำเตือน: 12 รายการ (ทุกรายการคือ "ไม่มีลิงก์ CV" ซึ่งเป็นข้อมูล optional)
ข้อผิดพลาด: 0
สถานะ: PASSED_WITH_WARNINGS
```

ไฟล์ที่อัปเดตไว้จริงใน repo (ไม่ได้อยู่ในโฟลเดอร์ `evidence/` เพราะยังไม่ได้สร้าง):

- `data/v1/source/faculty_profiles.json`, `data/v1/source/source-metadata.json` — controlled snapshot จริง 22 คน
- `build/v1/metadata/manifest.json`, `build/v1/metadata/preparation-summary.json` — สรุปชุดข้อมูลจริง
- `build/v1/serving/faculties.json`, `build/v1/serving/faculties/{id}.json` — ผล serving JSON จริงทั้ง 22 คน
  - เช่น `prapaporn-rattanatamrong.json` — ตัวอย่างข้อมูลครบ (มี CV, badge, ผลงาน)
  - เช่น `thapana-boonchoo.json` — ตัวอย่างข้อมูลไม่ครบ (ไม่มี CV) เพื่อยืนยันว่าระบบจัดการ missing data ได้อย่างปลอดภัย

บันทึกการตัดสินใจตอนเตรียมข้อมูลจริง (เช่น ชื่อไทย/อังกฤษของอาจารย์ท่านหนึ่งไม่ตรงกันแต่คงไว้ตาม
ต้นฉบับ, เบอร์ติดต่อที่ต่างกันระหว่างหน้า directory กับหน้าโปรไฟล์, ลิงก์วิชาการของอาจารย์ท่านหนึ่ง
ที่ชี้ผิดไปยังอีกท่านจึงถูกตัดออก, กรณีมีอีเมลมากกว่า 1 ช่องทางแต่ contract รองรับได้ช่องทางเดียว,
และการแก้ไขตัวอักษรเกินตกหล่นจากการ copy source) ถูกบันทึกไว้ในเอกสารหลัก หัวข้อ 12.4
"Data quality decisions made during preparation" แล้ว ไม่ได้แยกเป็นไฟล์ต่างหาก

**สถานะ:** ✅ ข้อมูลและสคริปต์เสร็จสมบูรณ์และตรวจสอบซ้ำแล้ว (รันสคริปต์จริงในเครื่อง ผลตรงกับไฟล์ที่ได้รับมา) — ⬜ ยังไม่ได้จัดเป็นแพ็กเกจ `evidence/` แยกต่างหาก

## README / Handoff

README ต้องทำตามได้จริง ไม่ใส่คำสั่งที่ไม่ได้ใช้จริง ประกอบด้วย:

1. สิ่งที่ต้องมีก่อนเริ่ม (prerequisites)
2. clone repo
3. ติดตั้ง frontend
4. ตั้งค่า env
5. ตำแหน่งไฟล์ source snapshot
6. คำสั่งรัน `python scripts/prepare_faculty_data.py`
7. ขั้นตอนของ Lambda/backend
8. คำสั่งรัน Next.js
9. ตรวจสอบหน้า `/faculties`
10. ตรวจสอบหน้า `/faculties/{id}`

## สรุปสิ่งที่เหลือให้ทีมทำต่อ (ทำแทนไม่ได้)

รายการด้านล่างนี้ต้องให้คนในทีมที่มีสิทธิ์เข้าถึงระบบจริงเป็นคนทำ เพราะเป็นข้อมูล/หลักฐานที่ต้อง
มาจากระบบที่ deploy จริง ไม่ใช่สิ่งที่เขียนโค้ด/เอกสารแทนได้:

1. เอา URL production จริงจาก Vercel มาใส่ในเอกสาร (`docs/v1/V1_Final_Documentation_Architecture_Decisions_Demo_Evidence.md`)
2. เข้า AWS Console เพื่อ capture หลักฐาน: S3 structure, Block Public Access, Lambda config,
   IAM role/policy, API Gateway routes/stage
3. ยิง API จริงเพื่อ capture response: list 200, detail 200, unknown 404, invalid id 400,
   unsupported method
4. เปิดเว็บจริงเพื่อ capture หน้าจอ: Directory/Profile ทั้ง desktop และ mobile, สถานะ loading/error/not-found
5. ทดสอบความปลอดภัยจริงแล้ว capture ผล: เข้า S3 ตรงๆ ถูกปฏิเสธ, Lambda เขียน/ลบไม่ได้, CORS ทำงานถูกต้อง
6. รวมผล E2E จาก Issue #28 มาใส่ในเอกสาร
7. สร้างโฟลเดอร์ `evidence/` จริงเมื่อพร้อม (ดู §49 ในเอกสารหลักสำหรับโครงสร้างที่ตกลงไว้)
   แล้วใส่ screenshot/ไฟล์ตามข้อ 2–6 ด้านบน
8. นัดทีมรีวิวเอกสารฉบับสุดท้ายและเซ็นอนุมัติปิด Issue #29
