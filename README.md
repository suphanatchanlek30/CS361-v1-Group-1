# Faculty Output & Workload Management System

ระบบกลางสำหรับจัดเก็บและเผยแพร่ข้อมูลผลงานและภาระงานของอาจารย์ในระดับสาขาวิชา

> เอกสารนี้เป็นภาพสรุปความเข้าใจร่วมกันของทีม ณ ปัจจุบัน ไม่ใช่เอกสารฉบับสมบูรณ์
> และจะถูกปรับปรุงเมื่อการออกแบบเปลี่ยนแปลง

| | |
|---|---|
| เวอร์ชันปัจจุบัน | V1 — Faculty Profile / Public Output |
| ลักษณะของ V1 | Information Service แบบอ่านอย่างเดียว ไม่ต้องเข้าสู่ระบบ |
| เอกสารอ้างอิง | Issue #1 Project Definition, Issue #2 System Boundary |

## Project Vision

ระบบกลางของสาขาวิชาสำหรับข้อมูลผลงานและภาระงานของอาจารย์
ที่เริ่มจากการเผยแพร่ข้อมูลอาจารย์ให้บุคคลภายนอกเข้าถึงได้
แล้วเติบโตไปสู่การให้อาจารย์ดูแลข้อมูลของตนเอง
มีกระบวนการตรวจสอบและรับรองข้อมูลตามบทบาท
และสรุปภาพรวมข้ามอาจารย์หลายคนหลายปีการศึกษา

ปลายทางคือ สาขาวิชาสามารถจัดทำร่างภาระงานและรายงานประจำปี
จากข้อมูลและกติกาที่ตรวจสอบย้อนกลับได้ว่ามาจากรายการใด

### ทิศทางการพัฒนา V1–V7

| Version | ชื่อ | สาระสำคัญ |
|---|---|---|
| **V1** | Faculty Profile / Public Output | เผยแพร่ข้อมูลอาจารย์และผลงานที่เปิดเผยได้ โดยไม่ต้องเข้าสู่ระบบ |
| V2 | Faculty Output Repository | จัดเก็บข้อมูลอย่างเป็นระบบ รองรับหลายปีการศึกษา ค้นหาและกรองตามเงื่อนไข |
| V3 | Secure Faculty Workspace | เข้าสู่ระบบ กำหนดสิทธิ์ตามบทบาท และกระบวนการตรวจสอบรับรองข้อมูล |
| V4 | Department Reporting & Aggregation | รวบรวมและสรุปข้อมูลระดับสาขาวิชาข้ามหลายปี |
| V5 | Automation | สร้างและปรับใช้ Infrastructure ซ้ำได้ด้วย Infrastructure as Code |
| V6 | Performance & Cost | วัดผล ระบุ Bottleneck และปรับปรุงพร้อมหลักฐาน Before–After |
| V7 | Integrated System | บูรณาการทั้งระบบเพื่อรองรับร่าง Workload Sheet และรายงานประจำปี |

## Primary User

**นักศึกษาในสาขาที่กำลังเลือกอาจารย์ที่ปรึกษาโปรเจกต์หรือวิทยานิพนธ์**
เข้าใช้งานในฐานะผู้ใช้ทั่วไป ยังไม่ต้องเข้าสู่ระบบ

เลือกกลุ่มนี้เป็น Primary User ของ V1 เพราะเป็นผู้ใช้ที่ได้ประโยชน์ทันที
จากการอ่านข้อมูลเพียงอย่างเดียว ซึ่งสอดคล้องกับข้อกำหนดของ V1
ที่ต้องเป็น Information Service

ผู้ใช้กลุ่มอื่นตามโจทย์ ได้แก่ อาจารย์ เจ้าหน้าที่สาขา ผู้ตรวจสอบ
และผู้บริหาร จะเข้ามามีบทบาทเต็มรูปแบบในเวอร์ชันถัดไป

---

## Problem

นักศึกษาไม่รู้ว่าอาจารย์แต่ละคนในสาขาเชี่ยวชาญด้านใด
และกำลังทำงานวิจัยเรื่องอะไรอยู่ในปัจจุบัน
จึงตัดสินใจเลือกอาจารย์ที่ปรึกษาจากการบอกต่อของรุ่นพี่
หรือความคุ้นเคยจากวิชาที่เคยเรียน มากกว่าความตรงกันของหัวข้อ

ผลที่ตามมาคือ เข้าไปติดต่ออาจารย์ที่ไม่ตรงสาย เสียเวลาทั้งสองฝ่าย
และบางคนพลาดอาจารย์ที่เหมาะกว่าไปโดยไม่รู้ว่ามีอยู่

### สถานการณ์ปัจจุบัน

เมื่อถึงเวลาต้องเลือกอาจารย์ที่ปรึกษา นักศึกษาต้องหาข้อมูลเองจากหลายทาง

- ถามรุ่นพี่หรือเพื่อนว่าอาจารย์คนไหนดูแลเรื่องอะไร
- อนุมานจากวิชาที่อาจารย์สอน หรือดูป้ายหน้าห้องพักอาจารย์
- ค้นชื่ออาจารย์ทีละคนจากอินเทอร์เน็ต
- เปิดหน้าเว็บสาขา ซึ่งมักมีเพียงชื่อ ตำแหน่ง และช่องทางติดต่อ
- เดินไปสอบถามเจ้าหน้าที่สาขา

ในภาพใหญ่ ข้อมูลผลงานและภาระงานของอาจารย์ ทั้งการสอน งานวิจัย
งานบริการวิชาการ และการดูแลนักศึกษา กระจายอยู่ในหลายไฟล์หลายแหล่ง
และจัดเก็บในรูปแบบที่ต่างกัน จึงไม่มีชุดข้อมูลกลางที่นักศึกษาใช้อ้างอิงได้

### ผลลัพธ์ที่ต้องการ

นักศึกษาเปิดดูที่เดียวแล้วเห็นว่าอาจารย์แต่ละคนในสาขาเชี่ยวชาญด้านใด
และมีผลงานอะไรในช่วงหลัง จนคัดเหลืออาจารย์ที่ตรงกับหัวข้อของตน
เหลือไม่กี่คนได้ด้วยตนเอง ก่อนจะเดินไปติดต่อจริง
โดยไม่ต้องไล่ถามรุ่นพี่หรือค้นทีละชื่อ

สังเกตผลลัพธ์ได้จาก

- ค้นด้วยคำที่เกี่ยวกับด้านที่สนใจ แล้วได้รายชื่ออาจารย์ที่เกี่ยวข้อง
- ข้อมูลที่เห็นมาจากชุดเดียวกันทั้งสาขา ไม่ต้องหาต่อจากช่องทางอื่น
- ผลงานแต่ละรายการมีปีการศึกษากำกับ จึงบอกได้ว่าเป็นงานช่วงไหน

ผลพลอยได้ อาจารย์และเจ้าหน้าที่สาขาไม่ต้องตอบคำถามเดิมซ้ำ ๆ

## V1 Goal

**ผู้ใช้ทั่วไปสามารถเข้าถึงข้อมูลอาจารย์ในสาขาและผลงานที่เปิดเผยต่อสาธารณะได้
จากแหล่งเดียว พร้อมค้นหาและกรองตามด้านความเชี่ยวชาญ โดยไม่ต้องเข้าสู่ระบบ**

V1 ครอบคลุมเฉพาะ FR1 ตามโจทย์ ส่วน FR2 ถึง FR10
ถูกกันออกจากขอบเขตโดยตั้งใจ และระบุไว้แล้วว่าจะกลับมาที่เวอร์ชันใด

### บริบทของ V1

ระบบแสดงเฉพาะข้อมูลที่สาขาวิชามีอยู่แล้วและอนุมัติให้เปิดเผย
โดยนำเข้าข้อมูลตั้งต้นเพียงครั้งเดียวก่อนเปิดใช้งาน
ยังไม่มีการแก้ไขข้อมูลผ่านระบบ และยังไม่มีการเข้าสู่ระบบ

V1 จึงยังไม่ได้เป็นเจ้าของข้อมูลหรือ Source of Truth
ความเป็นเจ้าของยังอยู่ที่สาขาวิชา
ระบบทำหน้าที่นำข้อมูลมาแสดงในรูปแบบที่ค้นหาและกรองได้เท่านั้น

## V1 In scope

### ข้อมูลที่ระบบจัดเก็บและแสดง

- ชื่ออาจารย์
- ตำแหน่งทางวิชาการหรือตำแหน่งงาน
- ด้านความเชี่ยวชาญ
- ข้อมูลติดต่อ
- ผลงานหรือสิ่งพิมพ์ที่เปิดเผยต่อสาธารณะได้
- ปีการศึกษาที่กำกับผลงานแต่ละรายการ
- วันที่ปรับปรุงข้อมูลล่าสุดของชุดข้อมูล

### ความสามารถของระบบ

- แสดงรายชื่ออาจารย์ทั้งสาขา
- แสดงโปรไฟล์รายบุคคลพร้อมรายการผลงาน
- ค้นหาอาจารย์ด้วยชื่อ
- ค้นหาและกรองตามด้านความเชี่ยวชาญ
- แสดงรายการผลงานหรือสิ่งพิมพ์พร้อมปีการศึกษา

### ข้อมูลตั้งต้น

ชุดข้อมูลที่นำเข้าจากไฟล์ของสาขาวิชาเพียงครั้งเดียวก่อนเปิดใช้งาน
การนำเข้าถือเป็นขั้นตอนเตรียมข้อมูล ไม่ใช่ความสามารถที่ผู้ใช้เรียกใช้ได้

### ความรับผิดชอบที่ยังคงอยู่นอกระบบ

- การสร้างและดูแลข้อมูลอาจารย์ต้นฉบับ
- การดูแลข้อมูลผลงานและสิ่งพิมพ์ต้นฉบับ
- การตัดสินใจว่าข้อมูลใดเปิดเผยต่อสาธารณะได้
- การตรวจสอบความถูกต้องของข้อมูลอาจารย์
- การปรับปรุงข้อมูลเมื่อมีการเปลี่ยนแปลง
- กระบวนการอนุมัติของอาจารย์และเจ้าหน้าที่

### ไม่อยู่ในขอบเขตของโครงการเลย

- ระบบทะเบียนบุคลากรหรืองานบุคคลของมหาวิทยาลัย
- การประเมินผลการปฏิบัติงานของอาจารย์
- การจัดการรายวิชาและตารางสอน
- การนัดหมายหรือติดต่อสื่อสารระหว่างนักศึกษากับอาจารย์

## External actors / systems

### External Actors

| Actor | ปฏิสัมพันธ์กับระบบใน V1 |
|---|---|
| นักศึกษาที่กำลังเลือกอาจารย์ที่ปรึกษา (Primary) | ดูรายชื่ออาจารย์ โปรไฟล์ และผลงาน ค้นหาและกรอง |
| ผู้ใช้ทั่วไปอื่น เช่น บุคคลภายนอกที่มองหาผู้เชี่ยวชาญ | ใช้งานได้เช่นเดียวกัน โดยไม่ต้องเข้าสู่ระบบ |
| เจ้าหน้าที่สาขา | จัดเตรียมและส่งมอบไฟล์ข้อมูลตั้งต้น ไม่ได้ใช้งานระบบโดยตรง |

**ยังไม่เป็น actor ใน V1**

- อาจารย์ — เข้ามาดูข้อมูลของตนเองได้ในฐานะผู้ใช้ทั่วไป แต่ยังบันทึกหรือแก้ไขข้อมูลไม่ได้ จะเป็น actor เต็มรูปแบบใน V3
- ผู้ตรวจสอบ หรือผู้รับรองข้อมูล — เริ่มมีบทบาทใน V3
- ผู้บริหาร หรือผู้ดูแลระบบ — เริ่มมีบทบาทใน V4

### External Systems / Data Sources

**ไฟล์ข้อมูลอาจารย์และผลงานที่สาขาวิชาจัดเก็บอยู่เดิม**

- เป็นแหล่งข้อมูลตั้งต้นเพียงแหล่งเดียวของ V1
- นำเข้าครั้งเดียวก่อนเปิดใช้งาน ไม่ได้เชื่อมต่อแบบอัตโนมัติ
- สาขาวิชาเป็นเจ้าของ ระบบเป็นเพียงผู้นำมาแสดง

V1 ยังไม่พึ่งพาระบบภายนอกอื่น เช่น ระบบทะเบียน ระบบบุคลากร
ฐานข้อมูลงานวิจัยภายนอก หรือระบบยืนยันตัวตนของมหาวิทยาลัย

### Boundary Flows

**เข้าสู่ระบบ**

| จาก | เข้ามาเป็นอะไร | เมื่อใด |
|---|---|---|
| ไฟล์ข้อมูลของสาขาวิชา | ข้อมูลอาจารย์และรายการผลงานที่เผยแพร่ได้ | นำเข้าครั้งเดียวก่อนเปิดใช้งาน |
| นักศึกษาและผู้ใช้ทั่วไป | คำค้นและเงื่อนไขการกรอง | ทุกครั้งที่เข้าใช้งาน |

**ออกจากระบบ**

| ไปยัง | ออกไปเป็นอะไร |
|---|---|
| นักศึกษาและผู้ใช้ทั่วไป | รายชื่ออาจารย์ โปรไฟล์รายบุคคล รายการผลงาน และผลการค้นหา |

**ไม่มีการไหลของข้อมูลในทิศทางต่อไปนี้**

- ผู้ใช้ส่งข้อมูลเข้ามาบันทึกในระบบ
- ระบบส่งข้อมูลออกไปยังระบบอื่นหรือส่งออกเป็นรายงาน
- ระบบดึงข้อมูลจากระบบภายนอกแบบอัตโนมัติ

### Data Ownership / Source of Truth

| ข้อมูล | Source of Truth | สถานะของระบบใน V1 |
|---|---|---|
| ข้อมูลอาจารย์ (ชื่อ ตำแหน่ง ความเชี่ยวชาญ ช่องทางติดต่อ) | ไฟล์ที่สาขาวิชาจัดเก็บ | Consume |
| รายการผลงานที่เผยแพร่ได้ | ไฟล์ที่สาขาวิชาจัดเก็บ | Consume |
| การกำหนดว่าผลงานรายการใดเผยแพร่ได้ | สาขาวิชาเป็นผู้ตัดสิน | Consume |
| การจัดหมวดหมู่และปีการศึกษาที่กำกับผลงาน | ระบบจัดโครงสร้างขณะนำเข้า | Own |

ใน V1 ระบบยังไม่ได้เป็นเจ้าของข้อมูลผลงานอาจารย์
Source of Truth ยังอยู่นอกระบบ คือไฟล์และเอกสารที่สาขาวิชาถือครอง

หากข้อมูลต้นทางเปลี่ยนแปลง ระบบจะไม่รับรู้โดยอัตโนมัติ ต้องนำเข้าใหม่ทั้งชุด
จึงต้องแสดงวันที่ปรับปรุงข้อมูลล่าสุดให้ผู้อ่านประเมินความสดของข้อมูลได้เอง

ความเป็นเจ้าของข้อมูลจะย้ายเข้ามาอยู่ในระบบเมื่อถึง V3
ซึ่งอาจารย์บันทึกข้อมูลของตนเองได้และมีกระบวนการตรวจสอบรับรอง

## Assumptions

- ข้อมูลอาจารย์และผลงานตั้งต้นมีอยู่แล้วในรูปแบบไฟล์ที่นำเข้าได้
- สาขาวิชามีเกณฑ์หรือรายการที่ระบุได้ว่าข้อมูลใดเปิดเผยต่อสาธารณะได้
- ข้อมูลที่เผยแพร่คือผลงานที่เป็นสาธารณะอยู่แล้ว ส่วนภาระงานสอนและจำนวนนักศึกษาในที่ปรึกษาถือเป็นข้อมูลภายใน
- V1 ไม่มีการแก้ไขข้อมูลผ่านระบบ ทั้งจากอาจารย์และเจ้าหน้าที่ การปรับปรุงทำโดยนำเข้าไฟล์ชุดใหม่ทั้งชุด
- ข้อมูลโปรไฟล์และผลงานเปลี่ยนแปลงไม่บ่อย จึงยอมรับความล่าช้าของข้อมูลได้
- ปริมาณผู้ใช้ในช่วงแรกไม่สูง และจำนวนอาจารย์อยู่ในระดับสาขา จึงยังไม่ต้องออกแบบเพื่อรองรับการขยายตัว

## Working Agreement

ทีมใช้ Issue เป็นหลักฐานการทำงาน ไม่ใช่รายการสิ่งที่ต้องทำ

```
Requirement → Issue → Branch → Implementation → Pull Request → Merge → Close Issue
```

- ทุกการเปลี่ยนแปลงเข้าสู่ main ผ่าน Pull Request ที่มีการ review
- ปิด Issue ด้วยหลักฐานการทำงาน เช่น Pull Request หรือผลการทดสอบ
